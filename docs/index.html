Resaltado semántico sin dependencias ni build

preSintaxis.js es un resaltador de sintaxis minimalista para HTML estático. En lugar de tokens genéricos, clasifica el código en categorías con significado: palabra reservada, tipo, valor, operador y comentario.

Semántico de verdad

Cada regla declara qué representa el token, no un color. Cambiar de tema es cambiar variables CSS.

El núcleo ronda los 2 KB gzip, sin dependencias, sin paso de compilación y con lenguajes por separado.

Extensible

Registra lenguajes propios y plugins que se enganchan al ciclo de tokenizado y renderizado.

Cada bloque es una región enfocable con etiqueta ARIA y botones reales para copiar o descargar.

Capítulos

Módulo 1

¿Qué es preSintaxis.js?

preSintaxis.js es una librería de resaltado de sintaxis para HTML estático. A diferencia de otros resaltadores, no asigna colores directamente: clasifica el código en categorías semánticas y deja que el CSS decida cómo se ven.

Cómo funciona

  • Marcas un bloque con <pre> y <code data-sintaxis="…">.
  • El núcleo tokeniza el texto con las reglas del lenguaje y agrupa los tokens por línea.
  • El resultado se escapa y se envuelve en <span class="ps-…">.
  • Los plugins añaden descarga, resaltado de líneas, búsqueda, diff, terminal, ejecución de ejemplos y más.

                // Cada token recibe una categoría, no un color
                const total = items.length;
                function sumar(a, b) { return a + b; }

                // palabra: const, function, return
                // tipo: number, string, Array
                // valor: 42, "texto", true
Versión 1.0.2 · Licencia MIT. El núcleo se autoinicia cuando el documento termina de cargar; los lenguajes y plugins deben cargarse antes que tu propio script.

Solo necesitas el núcleo y los lenguajes que vayas a mostrar. Carga los scripts en orden, antes de tu propia lógica, y deja que el núcleo procese los bloques existentes al cargar el documento.

Módulo 3

Uso básico

Marca el bloque con data-sintaxis en el <code>. La librería escapa el texto al renderizar, recorta la indentación común y respeta los saltos de línea. Si tu ejemplo contiene etiquetas HTML, escribe &lt; y &gt; en el archivo fuente: el navegador las interpreta antes de que la librería pueda escaparlas.

El núcleo solo procesa los <pre> que contienen un <code>; si falta, el bloque se ignora sin errores. 


                <pre data-encabezado="saludo.js" data-ajuste="copiar: true, lineas: true, resaltar: 2-3">
                  <code data-sintaxis="javascript">
                    // Hola, preSintaxis
                    const saludo = 'Hola, mundo';
                    console.log(saludo);
                  </code>
                </pre>

Atributos reconocidos

AtributoDóndeFunción
data-sintaxis<code>Identificador del lenguaje.
data-lang<code>Alternativa a data-sintaxis.
data-encabezado<pre>Barra superior con el nombre del archivo.
data-ajuste<pre>Pares clave: valor con o sin llaves.

Inicialización manual

El núcleo procesa el documento al cargar. Si insertas contenido después (por ejemplo, al cambiar de pestaña), reinicia solo ese contenedor: 


                // Solo procesa los 
 que aún no tienen data-sintaxis-listo
                preSintaxis.init(document.querySelector('#contenido'));

                // Revierte un bloque a su texto original (útil para demos)
                preSintaxis.destruir('#demo pre');

Módulo 4

Lenguajes y reglas

Un lenguaje es un arreglo de reglas { regex, tipo }. El orden importa: se evalúan de izquierda a derecha, así que los comentarios y las cadenas deben ir antes que los operadores. Los identificadores se normalizan a minúsculas, de modo que JavaScript y javascript apuntan al mismo lenguaje.

Categorías semánticas

TipoClase generadaVariable CSS
palabra.ps-palabra--ps-palabra
identificador.ps-identificador--ps-identificador
operador.ps-operador--ps-operador
delimitador.ps-delimitador--ps-delimitador
tipo.ps-tipo--ps-tipo
valor.ps-valor--ps-valor
comentario.ps-comentario--ps-comentario

Registrar un lenguaje propio


                preSintaxis.registrarSintaxis('toml', [
                  { tipo: 'comentario', regex: /#[^\n]*/ },          // primero: gana al resto
                  { tipo: 'valor',      regex: /"[^"]*"|'[^']*'/ },  // cadenas
                  { tipo: 'tipo',       regex: /\[[^\]\n]+\]/ },     // [seccion]
                  { tipo: 'palabra',    regex: /\b(?:true|false)\b/ },
                  { tipo: 'operador',   regex: /=/ }
                ]);
Usa grupos sin captura (?:…) dentro de tus reglas. La librería combina todas las expresiones en una sola y necesita controlar sus propios grupos.
Sin lenguaje cargado: si data-sintaxis no coincide con ningún archivo de dist/lang/, el bloque se muestra como texto plano. El identificador texto también fuerza ese modo.

Módulo 5

Ajustes y plugins

Los ajustes se declaran en data-ajuste como pares clave: valor separados por comas. El formato oficial usa llaves y valores entre comillas —data-ajuste="{copiar: 'true', lineas: 'true'}"—, aunque también se acepta sin llaves. Cada opción la aporta el núcleo o un plugin; si el plugin no está cargado, la opción se ignora sin errores.

Plugins oficiales

Los 13 archivos de dist/plugins/ se cargan después del núcleo; cada uno registra su plugin y su opción automáticamente. Carga solo los que uses.

  • temas.js: aplica dracula, nord o github-light.
  • resaltar.js, descargar.js, scroll.js: mejoras del bloque de código.
  • buscar.js, compartir.js, enlaces.js: búsqueda interior y difusión.
  • diff.js, terminal.js: coloreado especial de líneas.
  • sanitizar.js, ejecutar-javascript.js, playground.js: limpieza y demos interactivas.
  • carga-diferida.js: observador de intersección para bloques con lazy:'true' (experimental).
Precaución: ejecutar-javascript.js ejecuta el código del bloque con new Function() y playground.js lo interpreta en un iframe. Úsalos solo con ejemplos de confianza.

Crear un plugin


preSintaxis.registrarPlugin('nombreDelPlugin', (api) => {
  // 1. Inyectar estilos (si es necesario)
  const style = document.createElement('style');
  style.textContent = `...`;
  document.head.appendChild(style);

  // 2. Escuchar el hook del core
  api.hook('despuesDeRenderizar').registrar(({ pre, code, wrapper, ajustes, texto }) => {
    if (ajustes.nombreDelPlugin !== 'true') return;
    
    // 3. Añadir la funcionalidad al bloque
    // ...
  });
});

Módulo 6

Temas

El núcleo inyecta su CSS en un <style id="ps-estilos"> con un bloque :root de variables. Aplicar un tema consiste en reemplazar ese bloque; no hay que tocar el HTML ni volver a tokenizar.

Variables CSS de preSintaxis.js
VariableUso
--ps-contenidoFondo del bloque
--ps-encabezadoBarra del título del archivo
--ps-textoTexto base y del código
--ps-palabraPalabras reservadas
--ps-identificadorVariables, funciones y clases
--ps-operadorOperadores y signos lógicos
--ps-delimitadorParéntesis, llaves, corchetes y comas
--ps-tipoTipos y funciones integradas
--ps-valorCadenas, números y literales
--ps-comentarioComentarios

El plugin incluye dracula, nord y github-light. Este sitio añade atom-one-dark y monokai con la misma técnica y recuerda tu elección en localStorage. 


                // 1) Temas del plugin oficial
                window.preSintaxisTemas.temas;      // ['dracula', 'nord', 'github-light']
                window.preSintaxisTemas.aplicar('nord');

                // 2) Tema propio: reemplaza el bloque :root inyectado
                const variables = {
                  '--ps-contenido': '#1e1f1c',
                  '--ps-texto': '#f8f8f2',
                  '--ps-palabra': '#f92672',
                  '--ps-tipo': '#66d9ef',
                  '--ps-valor': '#e6db74',
                  '--ps-comentario': '#75715e'
                };

                const estilos = document.getElementById('ps-estilos');
                const bloque = ':root {\n' + Object.entries(variables)
                  .map(([clave, valor]) => `${clave}: ${valor};`)
                  .join('\n') + '\n}';

                estilos.textContent = estilos.textContent.replace(/:root\s*\{[\s\S]*?\}/, bloque);

Módulo 7

API de referencia

Todo se expone en el objeto global window.preSintaxis. Los métodos devuelven la propia API, por lo que se pueden encadenar.

MiembroDescripción
versionVersión actual: 1.0.2.
init(root)Procesa los <pre> pendientes dentro de root (por defecto, document).
destruir(selector)Quita el resaltado y restaura el texto original.
registrarSintaxis(id, reglas)Añade o reemplaza un lenguaje.
registrarPlugin(nombre, fn)Ejecuta el plugin una sola vez con la API como argumento.
hook(nombre).registrar(fn)Suscribe una función a un punto del ciclo de renderizado.

Hooks disponibles

HookRecibePuede devolver
antesDeTokenizar{ lenguaje, texto, ajustes, pre, code }{ lenguaje, texto }
despuesDeTokenizar{ lineas, lenguaje, ajustes, pre, code }{ lineas }

                // Un plugin que normaliza el lenguaje antes de tokenizar
                preSintaxis.registrarPlugin('alias-ts', (api) => {
                  api.hook('antesDeTokenizar').registrar((ctx) => {
                    if (ctx.lenguaje === 'typescript') {
                      return { lenguaje: 'javascript', texto: ctx.texto };
                    }
                  });
                });

                // Uso directo de la API
                preSintaxis.registrarSintaxis('sh', [
                  { tipo: 'comentario', regex: /#[^\n]*/ },
                  { tipo: 'palabra', regex: /\b(?:if|then|fi|for|do|done)\b/ },
                  { tipo: 'valor', regex: /"[^"]*"/ }
                ]);

Módulo 8

Buenas prácticas

  • Carga solo los lenguajes que realmente muestras: cada archivo es independiente.
  • Para producción, fija un tag o un commit del CDN en lugar de la rama @main, que cambia con el repositorio.
  • Declara las reglas de comentarios y cadenas antes que las de operadores.
  • Evita duplicar el CSS del resaltado: usa las variables semánticas y un solo tema.
  • Si generas contenido dinámico, llama a init(contenedor) después de insertarlo.

Limitaciones conocidas

  • No es un parser real: aplica expresiones regulares en orden, así que JSX, HTML dentro de JavaScript o plantillas anidadas se colorean de forma aproximada.
  • En bloques de más de 500 líneas el motor de expresiones regulares puede ralentizarse; conviene activar scroll.js o dividir el ejemplo.
  • El lenguaje debe declararse con data-sintaxis (o data-lang); no hay detección automática.

Notas de implementación

El tokenizador trabaja sobre el texto crudo y escapa cada token al renderizar. Por eso el coloreado es correcto incluso cuando hay etiquetas HTML dentro de una cadena o un comentario.

Los estilos base se inyectan en <style id="ps-estilos"> y el contenido se envuelve en .ps-contenido, lo que evita los saltos de línea y márgenes asimétricos clásicos de <pre> y <code>.

Preguntas frecuentes

¿Necesito jQuery, Prism o highlight.js?

No. preSintaxis.js no tiene dependencias y no compite con otros resaltadores: si ya usas uno, no cargues ambos sobre los mismos bloques.

¿Cómo muestro el código HTML sin que el navegador lo interprete?

Escribe el contenido dentro de <code> con las entidades &lt; y &gt;, o genera la página desde una plantilla que escape el texto. La librería escapa al renderizar, pero el navegador ya interpretó el HTML antes.

¿Funciona con React, Vue o Svelte?

Sí, siempre que inicialices después del renderizado del componente: preSintaxis.init(ref.current) o el equivalente en tu framework.

¿Por qué mi bloque no se resalta?

Revisa que el <code> tenga data-sintaxis con un lenguaje cargado y que el archivo del lenguaje se haya ejecutado antes que init(). Los bloques ya procesados llevan data-sintaxis-listo.

¿Puedo cambiar el HTML generado?

Sí. Los hooks antesDeRenderizar y despuesDeRenderizar permiten transformar el HTML o decorar el bloque sin modificar la librería.

Accesibilidad: cada bloque procesado recibe role="region" y aria-label, y es enfocable con tabindex="0"; los botones de copiado y descarga son button reales.
